    Execute three repository configuration commands via `gh api`. These are prerequisites for D-04 (auto-merge) and safe CI gating.

    **Step 1: Enable auto-merge on the repository.**
    Run: `gh api -X PATCH repos/Djarvur/cc-mplace -f allow_auto_merge=true`
    This enables the "Allow auto-merge" repo setting that is currently false. Without this, `gh pr merge --auto` in the workflow will fail with "auto-merge is not enabled for this repository."

    **Step 2: Create the "automated" label.**
    Run: `gh api -X POST repos/Djarvur/cc-mplace/labels -f name="automated" -f color="ededed" -f description="Automated PR (Dependabot)"`
    Per RESEARCH.md Pitfall 5, Dependabot silently ignores labels that don't exist. The `dependencies` label is auto-created by Dependabot on first run, but `automated` is custom and must be created manually. Use gray color "ededed" for a neutral appearance.

    **Step 3: Configure branch protection on main.**
    Run: `gh api -X PUT repos/Djarvur/cc-mplace/branches/main/protection --input -` with the following JSON payload:
    - required_status_checks: strict: true, contexts: ["validate"] (the job name confirmed from the successful CI run -- gh api showed the job name is "validate")
    - enforce_admins: true (admin pushes also require CI to pass)
    - required_pull_request_reviews: null (no review required for this single-author project)
    - restrictions: null (no push restrictions)

    Per RESEARCH.md Pitfall 3: Without branch protection requiring status checks, auto-merge can merge immediately before CI completes, which defeats the safety purpose. The `validate` check must be required so auto-merge queues and waits for CI to pass.

    After all three commands, verify each setting with follow-up gh api queries to confirm the changes took effect. If any command fails with a permissions error, report the exact error and suggest the user enable the setting via GitHub UI (Settings > General > Pull Requests > Allow auto-merge, or Settings > Branches > Branch protection rules).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dependabot service -> PR | External service creates PRs in the repo; PR content is untrusted until CI validates |
| Auto-merge workflow -> GitHub API | Workflow calls gh pr merge with repo-scoped GITHUB_TOKEN; token has write access to PRs and contents |
| PR merge gate | Branch protection on main requires "validate" status check; this is the primary safety control |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | Auto-merge workflow | mitigate | Workflow restricts to dependabot[bot] actor AND Djarvur/cc-mplace repo (double condition). Non-Dependabot PRs are ignored |
| T-04-02 | Elevation of Privilege | Auto-merge without CI gate | mitigate | Branch protection on main requires "validate" status check. Auto-merge queues until CI passes, does not bypass. enforce_admins: true prevents admin override |
| T-04-03 | Tampering | Malicious dependency auto-merge | mitigate | Cooldown delays version bumps 5 days, giving time for upstream supply chain issues to surface. Security updates merge immediately after CI only -- acceptable risk since CI validates schema and plugin sources |
| T-04-04 | Tampering | npm/GitHub Actions supply chain | accept | Dependabot fetches from official registries. CI validates the build. No PII or secrets in this static JSON project |
| T-04-SC | Tampering | GitHub Actions marketplace actions | mitigate | dependabot/fetch-metadata@v2 is the official Dependabot action from github.com/dependabot/fetch-metadata -- VERIFIED in RESEARCH.md Package Legitimacy Audit as Approved. actions/checkout and actions/setup-node are already in use from Phase 3 |
